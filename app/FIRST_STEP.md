# 第一关：让同一把茶壶左右各出现一份

先把相机基础设施迁入独立工程，确认能移动视点、改变朝向并正确处理深度。相机就绪后，你自己完成下面这一关：**共享一份茶壶几何，用两个物体的 model 矩阵摆出两把茶壶。**

长期路线见[项目方案](../PROJECT.md)和[A 档目标路线](../TO_A.md)。当前先建立多物体的数据关系，工作台随后逐件添加。

## 先认清三种数据

阅读 [Mesh.hpp](include/Mesh.hpp)，先区分“形状”和“场景里的一件物体”：

| 数据 | 保存什么 | 本关需要几份 |
| --- | --- | --- |
| MeshData | CPU 上的顶点位置、法线、三角形索引；描述茶壶的局部形状 | 一份生成结果 |
| Mesh | 上传后的 GPU 网格及绘制接口，拥有 VAO/VBO/EBO | 一份，由两个物体共同引用 |
| SceneObject | 你新增的物体描述：引用哪份 Mesh，以及自己的 model 矩阵 | 两份，分别摆左边和右边 |

共享 Mesh 表示两个对象使用同一套顶点和索引。它们的摆放状态各自保存，改变左边的 model 不应改变右边。Mesh 禁止按值复制；对象可以保存稳定的引用、指针或资源编号，拥有 Mesh 的位置要保证它比使用者活得久。

本关用两次普通绘制表达两个物体。先让“同一几何、不同摆放”成立，之后才需要考虑批量实例绘制等性能功能。

## model 矩阵负责把局部点摆到世界里

项目采用列向量，完整位置路径是

$$
\mathbf p_{\rm clip}=P\,V\,M\,\mathbf p_{\rm local}.
$$

按右侧先作用理解：M 把茶壶局部点变成世界点，V 将世界点变成相机坐标，P 得到裁剪坐标；透视除法发生在后面。移动物体改 M，移动相机改 V，不能用改相机来假装只移动其中一把茶壶。

纯平移矩阵的数学形式为

$$
T(t_x,t_y,t_z)=
\begin{pmatrix}
1&0&0&t_x\\
0&1&0&t_y\\
0&0&1&t_z\\
0&0&0&1
\end{pmatrix}.
$$

**列向量约定下，平移在最后一列。** 如果矩阵访问器采用“行、列”索引，三个平移量分别在第0/1/2行、第3列；这与内存按行还是按列连续存储是两件事。先确认项目数学类型的访问约定，再赋值。

第一关先令左右 model 分别是沿世界 x 的负、正平移，保持大小和朝向一致。可从茶壶包围半径 r 选择左右各偏移约 1.5r，随后按实际外形调整。相机也要后退到能同时看见两份的位置，旧的单物体取景范围未必够用。

用一个点检查：局部原点的齐次坐标是 $(0,0,0,1)$，经 T 后应成为 $(t_x,t_y,t_z,1)$。法线是方向，纯平移不应改变它。

## 你要沿哪条数据流修改

先看 [Main.cpp](src/Main.cpp) 中网格生成、上传和绘制的连接，再看 [Surface.vert](shaders/Surface.vert)。当前顶点 shader 直接把顶点当世界位置，只有 view、projection；这是单物体默认放在原位的约定。

你需要自己补出以下关系：

1. 在主程序中保存一个 SceneObject 容器，让两个对象引用同一个 GPU Mesh，各自保存 model。
2. 每帧使用同一相机的 view、projection；逐个物体绘制前，上传这个物体自己的 model，再调用其 Mesh 的 Draw。
3. 给顶点 shader 增加 model 输入。先取得世界位置，再由 view、projection 得到裁剪位置；送给世界空间光照的 position 也应是变换后的世界位置。
4. 同时保持法线空间一致。若光照在世界空间，法线使用

$$
\mathbf n_{\rm world}
\propto \left(M_{3\times3}^{-1}\right)^{T}\mathbf n_{\rm local},
$$

并在需要时单位化。纯平移时这部分是单位矩阵，所以第一关容易检查；后面桌板、桌腿会用非等比缩放，届时不能继续原样传递法线。先平移、不缩放，可以把当前问题集中在物体状态和逐次绘制上。

不要通过永久改写 MeshData 的所有顶点来移动其中一份：这样会改变共享形状，另一份也可能跟着变化。摆放属于 SceneObject，几何生成与 GPU 上传只在形状变化时发生。

## 现在独立完成的最小任务

保持现有茶壶的生成结果，显示两把大小、朝向相同的茶壶。左物体沿世界 x 负向放置，右物体沿正向放置；移动相机后仍能观察到它们各自固定在世界中的位置。

完成后做一次对照：只修改左物体的平移量，右物体的位置应保持不变。两份可以暂时同色，先用位置与遮挡确认数据流。

验收时回答：

- 两把茶壶共享了哪些数据，哪些数据必须分别保存？
- 为什么 model 要在每个物体 Draw 之前更新，而不是全部画完才更新？
- 只移动左物体时，顶点缓冲和相机 view 是否需要随之改变？
- 左物体位置正确但光照像留在原处，应检查哪一个 shader 输出的空间？

如果只看到一把，依次检查两个对象的 model 是否不同、每次 Draw 前上传了谁的矩阵、相机是否容纳两份；两份都使用单位 model 时完全重叠，画面本来就可能像只有一把。

## 后续逐件恢复工作台

第一关通过后，再一次添加一类几何，不把整张桌子的初始化一次写完。以下尺寸仅是项目示例，采用世界 y 向上；尺寸顺序为 x宽、y高、z深，假设基础立方体边长为1且中心位于局部原点。

| 顺序 | 下一次任务 | 示例尺寸与目标 |
| --- | --- | --- |
| 2 | 增加地板 | 8 × 0.1 × 6，上表面放在 y=0，检查前后遮挡 |
| 3 | 增加桌板 | 3 × 0.15 × 1.6，上表面高度可取 y=1.2；自己求中心高度 |
| 4 | 先做一条腿，再复用为四条 | 每条 0.15 × 1.05 × 0.15；脚落地、顶部接桌板下表面，自己推四个中心位置 |

进入非等比缩放前，先检查基础网格的实际边长和原点，再推 model 的组合顺序及法线变换。四条腿可以共享同一份立方体 Mesh，各有自己的 model；桌子连贯与否由尺寸和位置的关系决定，不靠复制四份顶点数据解决。

目前先停在“两把茶壶能独立摆放”，把你的 SceneObject 设计与绘制路径写出来，再检查下一件物体。
